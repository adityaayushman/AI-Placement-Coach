# Decisions

Format: date, decision, reason. Newest last.

## Phase 0 (2026-10-27)

1. **Repo root is the existing `placement coach` folder**, not a nested `ai-placement-coach/`. The folder already exists and holds the spec file; nesting adds no value.
2. **Local Python is 3.12, containers and CI use 3.11.** `requires-python = ">=3.11"`; code must not use 3.12-only features. CI is the source of truth.
3. **Tailwind v3** (PostCSS) rather than v4, for stable, widely documented config.
4. **Dependencies are split by phase.** Phase 0 `pyproject.toml` has only API/worker/test tooling. Heavy ML deps (torch, sentence-transformers, spaCy, faster-whisper) are added in the phase that needs them, to keep images and CI fast. Pinned lockfile/hashes arrive with the ML phases (reproducibility requirement).
5. **Worker is a stub in Phase 0**: RQ worker process starts and connects to Redis; no tasks yet.
6. **`/api/v1/health` is liveness only; `/api/v1/ready`** checks DB and Redis. Metrics endpoint comes with observability work in Phase 9 (request IDs and structured logs are in from Phase 0).
7. **No MongoDB.** PostgreSQL + JSONB only, per spec.
8. **Playwright e2e is deferred** to the first phase with a real user flow (Phase 1). Vitest is set up now.
9. **No database migrations in Phase 0.** Alembic is wired in Phase 1 together with the data model.
10. **Deployment targets: frontend on Vercel, backend on Render** (user instruction). `frontend/vercel.json` (SPA rewrite) and `render.yaml` (API web service, RQ worker, Postgres 16, Key Value/Redis) are provided but nothing is deployed. Docker Compose is for local development only. Consequences:
    - `VITE_API_URL` is a Vercel build-time env var pointing at the Render API URL; `CORS_ORIGINS` on Render must list the Vercel URL(s).
    - Render's `DATABASE_URL` is `postgres://`; Phase 1 must normalize it to `postgresql+psycopg://` in config.
    - Render free web tier sleeps and free Postgres expires: fine for a demo, not for the pilot. Uploaded files on local disk are lost on redeploy unless a Render persistent disk or S3/MinIO is used (decide in Phase 2). Heavy ML deps (Phase 4+) will need a larger Render instance.
    - The local `web` service in Compose stays as a production-like check of the frontend build.

## Phases 1-9 (2026-10-27, submission build)

The user asked to run every remaining phase back to back without stopping between them, because of a submission deadline. The local machine had a full C: drive (no pagefile growth, so memory allocation failures) and very slow PyPI downloads. These constraints drove several deviations:

11. **Heavy ML libraries sit behind interfaces with lightweight defaults.** sentence-transformers, spaCy, faster-whisper, librosa, XGBoost, SHAP and PyTorch could not be installed here. Defaults: TF-IDF word+char embeddings (`app/ml/embeddings.py`), an alias/regex skill matcher with difflib fuzzy fallback (in place of a spaCy matcher), numpy WAV prosody (in place of librosa), sklearn `HistGradientBoostingClassifier` (in place of XGBoost/LightGBM; XGBoost is used automatically if installed), and occlusion attribution (in place of SHAP, labelled as such in the UI and docs). `pip install ".[ml-heavy]"` plus `USE_SENTENCE_TRANSFORMERS` / `USE_FASTER_WHISPER` turns the heavier backends on. TF-IDF is lexical, so "semantic" match quality is lower than the spec intends.
12. **Password hashing uses stdlib scrypt** (RFC 7914 interactive parameters) instead of argon2/bcrypt, to avoid a native dependency. Hashes carry a `scrypt$` prefix so a later move to argon2 can verify-and-rehash.
13. **Email validation is a regex**, not `email-validator`, for the same reason.
14. **Speech-to-text**: server STT is optional (faster-whisper). The default flow uses the browser's Speech Recognition API where available, or typed answers. The browser converts audio to 16 kHz WAV, so the server needs no ffmpeg.
15. **The readiness model bootstraps on SYNTHETIC data** (`app/ml/readiness/synthetic.py`) at Docker build or first use. Every score stores `model_version` and `data_source`; the dashboard shows "Trained on synthetic data" while that is true. Retrain from a pseudonymised CSV with `train_and_register(csv)`.
16. **Alembic** has one snapshot revision (`0001_initial`, `create_all`). The API also runs an idempotent `create_all` at startup so a fresh demo needs no migration step. Future changes must be autogenerated revisions.
17. **Recommender**: unassessed prerequisites count as 0.7 mastery so they shape ranking without blocking core skills (found by the offline replay test). Ignored items are counted from `recommendations` rows, not `events`, so the loop still works when analytics consent is off.
18. **Interview content score** = 70% key-point coverage + 30% similarity to a reference answer; communication and delivery are transparent rules. LLM-as-judge was not built (no provider configured).
19. **DKT (LSTM)** and ASSISTments validation: not done (no PyTorch, dataset not downloaded).
20. **Facial analysis**: not built (stretch, off by default per spec).
21. **Rate limiting is in-process** (per API instance). Use a shared limiter when scaling out.
22. **Coordinator aggregates suppress groups smaller than 3** to limit re-identification. Individual rows and the CSV export include only students with `coordinator_visibility` consent, and every such read is audited.
23. **Local verification** borrowed already-installed packages from two other venvs on D: through `.pth` files in the untracked `.venv`. CI installs from PyPI normally.
24. **Frontend design**: dark "musk" palette (espresso, smoked mauve, dusty rose, sage, amber) with frosted-glass panels over blurred gradient light, per user request, following the ui-ux-pro-max checklist (4.5:1 text contrast, 44 px targets, visible focus, reduced motion, SVG icons).
25. **Render runs jobs inline** (`JOBS_INLINE=true`) so the free tier needs no paid worker; the RQ worker remains for Compose and paid plans.
